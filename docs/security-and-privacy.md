# セキュリティ・プライバシーの方針

個人開発と、このポートフォリオの公開にあたって守っている方針をまとめます。
実際の秘密情報や設定値はこのドキュメントを含め、リポジトリ内のどこにも記載していません。

## 1. 秘密情報の管理

- API キーやアクセストークンなどの認証情報は `.env` などの環境ファイルに置き、コードからは環境変数として読み込みます。
- 環境ファイルは `.gitignore` で除外し、リポジトリにはキー名だけを書いたサンプルファイルを置きます（値は書きません）。
- OAuth の認証ファイル（クライアント設定やリフレッシュ用の保存ファイル）は、リポジトリの外にあるユーザー設定ディレクトリに置きます。
- AI エージェントにも秘密情報を読ませません。環境変数の確認は「変数名と存在の有無」までにとどめ、値を表示させない運用にしています。
- 素材（BGM など）のうち再配布できないものはコミット対象から外しています。

## 2. Git 運用での防止策

- `git add` は対象ファイルを明示して行い、`-A` や `.` での一括追加は使いません。
- コミット前にステージされたファイル一覧を確認します。
- push の前に次の 5 点を確認し、疑いがあれば止めて判断します。
  1. 個人情報の混入（履歴・ログ・データファイル、氏名・連絡先）
  2. 機密情報の混入（環境ファイル、鍵ファイル、トークンらしき文字列）
  3. 大容量・バイナリ（動画・音声・依存関係ディレクトリ）
  4. コミットの粒度（目的の異なる変更の混在）
  5. 非可逆な操作（履歴の強制書き換えなど）
- 履歴の強制書き換えやブランチ削除などの非可逆操作は、必ず確認を取ってから行います。

## 3. AI エージェントに対する権限の制限

- エージェントに許可する操作は最小限にし、プロジェクトごとに設定します（例: ビルド・テストのコマンドのみ許可）。
- 一時的に広い権限が必要な作業は、コミットしないローカル設定に書き、作業後に戻します。
- 破壊的なコマンドや本番環境への操作は、エージェントの判断だけでは実行させず、確認を挟みます。
- 調査だけの作業は書き込み権限のないエージェントに任せ、調査が変更に化けないようにしています。

## 4. 個人情報・実運用データの扱い

- 家庭向けアプリの学習履歴や、店舗アプリの顧客・予約・売上のデータは、本人以外が見られない場所にだけ置き、ポートフォリオやスクリーンショットには使いません。
- 画面の例が必要な場合は、ダミーデータで撮り直したものだけを使います。
- 生成した動画・音声・実行ログは Git 管理外に置き、公開リポジトリには含めません。

## 5. Private リポジトリと Public ポートフォリオの分離

このポートフォリオは、開発中のリポジトリをそのまま公開したものではありません。

- 元のリポジトリはすべて Private のまま維持しています。
- このリポジトリは `git init` から新規に作成し、元リポジトリの Git 履歴を引き継いでいません。
- 収録しているのは新規に書いた説明文・構成図・確認済みの画像だけで、元リポジトリのソースコード・設定ファイル・データはコピーしていません。

### 公開していないもの

- 環境ファイル、API キー、トークン、認証情報、鍵ファイル
- 個人・家族に関する情報、連絡先、ローカル環境のパスやユーザー名
- 実際のアカウント名、チャンネル名、動画 ID、クラウドのプロジェクト名
- 実運用データ（アナリティクスの実数値、顧客・予約・売上、学習履歴）
- 定時実行や通知先の実設定値、非公開の URL
- 再配布できない素材（BGM・動画・画像）
- 勤務先に関する情報

## 6. 公開前のチェック

公開するファイルは、次の手順で確認しています。

1. 公開予定ファイルの一覧を作る
2. 認証情報・メールアドレス・ローカルパス・アカウント名・URL などのキーワードとパターンを全ファイルで検索し、該当がないことを確認する
3. 環境ファイル・鍵ファイル・認証用 JSON が存在しないことを確認する
4. 画像を目視し、個人情報・アカウント名・URL が映っていないことを確認する
5. Git 履歴が新規であることを確認する
6. 説明文の内容（機能・状態・数値）が元リポジトリの事実と一致していることを確認する
